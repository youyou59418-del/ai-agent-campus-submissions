# 工程复盘与下一步


## 最难的边界：引用存在不等于支持结论

文档 ID 正确，但数字换了、单位丢了、引用属于另一条政策，仍然可能误导员工。本题选择完整原子片段的抽取式回答：模型决定查什么、读什么、是否冲突；程序核对引用并保留原文事实。这个取舍减少事实改写风险，但不会自动提供任意长文摘要或通用语义证明。

## 日期、冲突与资料缺口

D02 比 D01 新，不足以证明 15 天优先于 30 天。实际模型读取两份后补查范围与优先级，仍缺依据时列出冲突并请求确认。资料更新使两份都为 30 天后又能正常回答，说明系统没有把“不同日期”硬编码成永远冲突。

相同追问有年假用户前文时可答，没有前文则先澄清。历史助手即使写出某个数字，也不能成为制度依据。这把对话理解与证据来源分开了。

## 来源新鲜度

改写 D01 为 45 天且不改日期后，第二轮答案同步变化。读取后把年假 3 改为 5 时，旧引用被拒绝并重新读取。进一步复核又发现“获校验后新增另一份冲突文档”的边界，因此增加整体语料哈希检查和离线回归。不能只证明某条引文还在，也要考虑当前闭集资料是否已经变化。

## 检索改进的有效范围

人工同义词表使八条合成查询的 Hit@1/Recall@4 从 62.5% 到 100%，但词表与查询都由人工设计，不能据此推断生产效果。真正部署前应独立采样员工问题、固定评测集、区分可答/冲突/拒答，并分别评估检索和引用支持。

## 下一步


1. 扩展独立问题集和更复杂的范围/版本冲突，评价主题解析误差与保守冲突的误报。
2. 若用于真实企业，再加入文档权限、来源真实性、解析与分块、明确权威规则、索引更新和大库检索；这些不是本次已完成能力。
