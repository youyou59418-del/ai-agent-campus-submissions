# 用户、目标和成功标准

用户是需要可编辑脚本的创作者。输入主题、受众、平台、时长上限和风格；材料为合成产品事实、表达库与品牌规则。系统交付标题、分镜、旁白/字幕、逐镜和总估算时长、素材 ID/原文、风险和状态。

## 范围与解释

时长按上限检查，不要求精确填满目标。输出为 JSON 和 Markdown，没有生成视频、TTS、素材图片或真实发布。事实严格采用完整素材原句；创作表达采用预置合成库，模型编排顺序、视觉与停留时间。该原型不声称任意自由文案都能被自动证明正确。

受众与平台是不可擅改的 brief，风格决定可用表达。合成表达库未经过真实品牌方审批，检查通过只表示符合本仓库的合成规则。资料只覆盖字幕/封面两个控制主题，复杂复合需求或库外表达需要扩展与人工复核。

## 必验与扩展

| 要求 | 成功标准 | 真实证据目录 |
|---|---|---|
| 正常生成 | 有标题、分镜、旁白/字幕、P01 引用和不超目标的时长；检查通过 | normal/ |
| 缺关键信息 | NEEDS_INPUT，列出字段；零模型调用 | missing_audience/、missing_duration/、missing_multiple/ |
| 无素材 | 改写或补查后请求补充，不编造 P01 或新功能 | no_materials/ |
| 工具失败 | 一次失败观察后重试，持续失败明确 TOOL_FAILURE，不交付未检查脚本 | search_failure_once/、estimate_failure_once/、rules_permanent_failure/ |
| 超时长修正 | 先观察 D0=38 秒不通过，改稿并重新估算和检查，最终不超 30 秒 | overlong_repair/ |
| 明确无法满足 | 5 秒约束下当前库最短估计仍过长，UNFULFILLED，无批准脚本 | impossible_duration/ |
| 品牌修正 | 初稿风格不匹配，模型改稿后重新检查通过 | brand_repair/ |
| 无事实依据的效果要求 | 没有 80% 数据时明确缺依据，不默默添加或省略该硬性要求冒充完成 | unsupported_claim/ |
| 改时长 | 30→20 后重新编排并满足新上限 | target_changed/ 两轮 |
| 改检索结果 | 移除 P01 后从有脚本变为请求素材 | retrieval_changed/ 两轮 |
| 动作上限 | STEP_LIMIT / INCOMPLETE，没有伪造通过结果 | step_limit/ |

目录均在 examples/live/。同名 examples/mock/ 仅证明手写策略的离线流程。16 个真实模式场景中三组缺参路径由前置校验处理，其余 13 组实际调用模型。

## 不可越过的边界

素材 ID、事实原句和分镜逐项对应；P01 仅支持“支持字幕。”，不能推导自动生成、性能提升或未提供的界面按钮。模型不能指定检查通过、覆盖时长上限或修改估算语速。修改后必须检查同一版本；数据变化后旧通过记录失效。未批准初稿、失败与风险保留在历史里，不作为最终 script。
